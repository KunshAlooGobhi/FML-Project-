# E-Commerce Recommendation System (Fundamentals of Machine Learning project)

A leakage-aware study of collaborative, content-based and hybrid recommenders on Amazon product and review data.

## Data (not committed; see `manifests/raw_manifest.json` for checksums)
- `amazon_ecommerce_1M.csv` - 1M purchases, 603,815 users, 89,999 products, dates 2024-03-31 to 2026-03-31. Appears synthetic.
- `products.csv`, `reviews.csv` - 728 real Amazon clothing products and 6,327 reviews. No user IDs; product IDs cannot be linked to the 1M file.

## Layout
`data/raw`, `data/processed`, `notebooks/`, `src/`, `manifests/`, `reports/`

## Documented deviations from the partial report
- k-core is **k=2**, not 5 (only 5,094 users have >=5 purchases). Cold-start tests keep the full data.
- The two datasets are used for different roles and are never merged.

## Findings so far (all numbers in `reports/`, generated by the code)
- `amazon_ecommerce_1M.csv` is consistent with purely random purchases (`reports/signal_diagnostics.md`): all baselines tie with random (NDCG@10 ~ 5e-5).
- **Positive control** (`src/make_control_data.py`): a SIMULATED dataset with a planted taste pattern. The same pipeline finds it (popularity NDCG@10 0.059 vs random 0.002), so the evaluation code is sound. It is synthetic and is never presented as real data.

## Phase 3 results (validation, warm users; `reports/models_validation_*.md`)
- Control (simulated, 4,903 users): item-kNN NDCG@10 0.183 > ALS 0.169 > BPR 0.137 > tuned popularity 0.059 > SVD 0.053 > random 0.003. Item-kNN/ALS/BPR beat popularity; biased SVD (a rating predictor) does not.
- 1M file (5,000 seeded warm validation users, reduced grids because of a 2-core / 3 GB machine): every model is at or near 0, so nothing is learnable, consistent with `reports/signal_diagnostics.md`.
- Best ALS/BPR settings on the control sit at the grid edge (factors=32); the control has only 8 latent dimensions.
- Ties in scores are broken by a tiny training-popularity bonus. Validation only; the locked test has not been scored.

## Phase 3-4 results (validation only; `reports/content_amazon.md`, `reports/hybrid_validation_control.md`)
- **Content model, real Amazon text** (no users, so a proxy task: same leaf category): held-out NDCG@10 0.567 vs random 0.038 and popularity 0.046. Review text helps (0.530 -> 0.567). Best Table II setting: max_features=5000, ngram (1,2).
- **Hybrid, simulated control only** (real text and real purchases cannot be linked): on warm users the best blend weight is w=0, i.e. content does not improve on item-kNN (NDCG@10 0.183 vs content-only 0.013).
- **Cold-item stress test** (200 items hidden from training): collaborative filtering scores 0; the adaptive hybrid (content-only for items with no history) reaches HitRate@10 4.2% at w=0.1 and 6.5% at w=0.3. Cost: NDCG@10 on ordinary purchases drops 0.189 -> 0.170 because new items take list slots.
- Control cold-item slice in the real validation split has only 7 rows, so the stress test is simulated.
